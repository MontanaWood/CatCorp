# Intercom

**Intercom** — локальный корпоративный мессенджер для обмена сообщениями и файлами внутри локальной сети предприятия.

Приложение построено по клиент-серверной архитектуре и работает без обязательного подключения к Интернету. Сервер управляет пользователями, чатами, историей сообщений и файлами, а клиент предоставляет графический интерфейс на PyQt6.

Клиент можно запускать как Python-приложение или собрать в самостоятельный `.exe` для Windows.

---

## Основные возможности

### Общение

- личные чаты между пользователями;
- групповые чаты;
- обмен сообщениями в реальном времени;
- история переписки;
- поиск по истории личного чата;
- ответы на сообщения;
- редактирование собственных сообщений;
- индикатор набора текста;
- разделители сообщений по датам;
- счётчики непрочитанных сообщений;
- закрепление и скрытие личных чатов;
- выход из текущего чата по клавише `Esc`.

### Обмен файлами

- отправка файлов в личные и групповые чаты;
- выбор нескольких файлов;
- добавление файлов через кнопку `+`;
- добавление файлов перетаскиванием в окно чата;
- отмена выбора файлов до отправки;
- скачивание файла двойным кликом или через контекстное меню;
- сохранение скачанных файлов в папку `Downloads/Intercom`;
- максимальный размер одного файла — 25 МБ;
- проверка целостности файлов на сервере по SHA-256.

### Пользователи и профили

- регистрация и вход;
- автоматический вход по токену;
- выход из аккаунта с завершением сессии;
- отображаемое имя;
- отдел и должность;
- статусы: доступен, занят, не беспокоить, отошёл;
- просмотр мини-профиля собеседника;
- отображение статуса онлайн/офлайн;
- административное управление пользователями.

### Уведомления

- уведомления через системный трей;
- звуковые уведомления;
- скрытие текста сообщения в уведомлении;
- отключение уведомлений для отдельного личного чата;
- отключение уведомлений для отдельной группы;
- сохранение настроек уведомлений локально.

### Интерфейс

- светлая и тёмная темы;
- сохранение выбранной темы;
- карточки личных и групповых чатов;
- пузырьки входящих и исходящих сообщений;
- отдельное оформление файловых сообщений;
- отображение ответов внутри сообщения;
- разделители дат в истории;
- плавная прокрутка;
- адаптированные полосы прокрутки;
- фирменная иконка окна, системного трея и `.exe`.

## Архитектура

Intercom состоит из трёх основных частей:

1. **Клиентское приложение**
   - интерфейс на PyQt6;
   - работа с чатами, файлами, уведомлениями и настройками;
   - TCP-подключение к серверу.

2. **Сервер**
   - обработка подключений;
   - авторизация пользователей;
   - маршрутизация личных и групповых сообщений;
   - работа с файлами;
   - обновление статусов и списков чатов.

3. **База данных**
   - пользователи;
   - личные и групповые сообщения;
   - комнаты и участники;
   - токены авторизации;
   - состояния прочтения;
   - сведения о загруженных файлах;
   - защита от перебора паролей.

Обмен между клиентом и сервером выполняется по TCP/IP с использованием JSON-протокола.

## Настройка MySQL / MariaDB

Для локального запуска можно использовать MySQL или MariaDB из состава XAMPP.

Имя базы данных по умолчанию:

```text
catcorp
```

Внутреннее имя базы сохранено для совместимости с текущей конфигурацией проекта и не зависит от внешнего названия приложения Intercom.

Перед первым запуском:

1. запустите MySQL/MariaDB;
2. создайте базу данных;
3. выполните SQL-скрипты из папки `database/`;
4. создайте отдельного пользователя базы данных для приложения;
5. заполните файл `.env`.

---

## Настройка `.env`

Создайте файл `.env` рядом с `server.py`.

```env
CATCORP_DB_HOST=127.0.0.1
CATCORP_DB_PORT=3307
CATCORP_DB_USER=catcorp_app
CATCORP_DB_PASSWORD=change_this_password
CATCORP_DB_NAME=catcorp
```

Переменные `CATCORP_DB_*` являются внутренними техническими идентификаторами и могут оставаться без переименования.

Файл `.env` содержит данные подключения и не должен публиковаться в репозитории.

## Запуск сервера

```powershell
python server.py
```

По умолчанию сервер слушает:

```text
0.0.0.0:5000
```

Для доступа с других компьютеров локальной сети необходимо разрешить входящие подключения к порту `5000` в Windows Firewall.

---

## Запуск клиента

```powershell
python client.py
```

На экране входа доступна кнопка **«Сервер»**, через которую можно указать IP-адрес серверного компьютера и порт.

Пример адреса:

```text
192.168.1.25
```

Порт по умолчанию:

```text
5000
```

Параметры сохраняются в локальный файл `server_config.json`.

## Локальные файлы клиента

Клиент создаёт локальные файлы только при необходимости:

```text
auth_token.json
settings.json
server_config.json
```

- `auth_token.json` — токен автоматического входа;
- `settings.json` — тема, уведомления и другие настройки;
- `server_config.json` — адрес и порт сервера.

Эти файлы не должны добавляться в Git.

---

## Хранение файлов

Сервер сохраняет переданные файлы в папку:

```text
uploads/
```

Для файла в базе данных хранятся исходное имя, внутреннее имя хранения, размер, SHA-256, отправитель, получатель или группа и дата загрузки.

Доступ к скачиванию предоставляется только участникам соответствующего личного или группового чата.

## Безопасность

В Intercom используются следующие меры:

- клиент не подключается к базе данных напрямую;
- пароли хранятся в виде bcrypt-хэшей;
- предусмотрена совместимость со старыми SHA-256-хэшами с последующим обновлением;
- токены автоматического входа хранятся на сервере в виде SHA-256-хэшей;
- старые токены пользователя удаляются при создании нового;
- данные подключения к БД вынесены в `.env`;
- используется отдельная учётная запись MySQL/MariaDB;
- после нескольких неудачных попыток вход временно блокируется;
- максимальная длина сообщения ограничена 4096 символами;
- максимальный размер файла ограничен 25 МБ;
- сервер проверяет права доступа к чатам, группам и файлам;
- повторная авторизация внутри уже авторизованного TCP-соединения отклоняется;
- имена загружаемых файлов очищаются перед сохранением;
- целостность скачиваемого файла проверяется по SHA-256.

---

## Ограничение попыток входа

После пяти неудачных попыток вход блокируется на 15 минут.

```text
5 попыток
15 минут блокировки
```

Сведения о блокировках хранятся в таблице `login_attempts`.

## Проверка работы в локальной сети

1. Запустите `server.py` на серверном компьютере.
2. Узнайте его локальный IP:

```powershell
ipconfig
```

3. Запустите клиент на другом компьютере.
4. На экране входа нажмите **«Сервер»**.
5. Укажите IP серверного компьютера и порт `5000`.

Проверка доступности:

```powershell
Test-NetConnection 192.168.1.25 -Port 5000
```
