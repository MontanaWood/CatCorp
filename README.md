# CatCorp Messenger

CatCorp Messenger — локальный корпоративный мессенджер для небольших команд и предприятий, работающий в локальной сети.

Проект состоит из:

* Python-сервера;
* MySQL/MariaDB базы данных;
* PyQt6-клиента;
* TCP-соединения с JSON-протоколом.

Клиент можно запускать как обычный Python-скрипт или собрать в самостоятельный `.exe` через PyInstaller.

---

## Возможности

* регистрация и вход пользователей;
* автоматический вход по токену, если включено **«Запомнить вход»**;
* личные чаты;
* групповые чаты;
* непрочитанные сообщения;
* закрепление и скрытие личных чатов;
* уведомления в системном трее;
* звук уведомлений;
* скрытие текста сообщений в уведомлениях;
* отключение уведомлений отдельно для каждого личного чата;
* отключение уведомлений отдельно для каждой группы;
* статусы пользователя;
* профиль пользователя;
* отдел и должность в профиле;
* мини-профиль собеседника;
* ответ на сообщение;
* редактирование своих сообщений;
* запрет редактирования сообщений старше 48 часов;
* индикатор печати;
* выход из текущего чата по `Esc`;
* встроенный дефолтный сервер `127.0.0.1:5000`;
* настройка host/port сервера через кнопку **«Сервер»** на экране входа;
* сборка клиента в самостоятельный `.exe`.

## Установка зависимостей

Рекомендуется использовать виртуальное окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
```

Если `requirements.txt` отсутствует, установите зависимости вручную:

```powershell
pip install PyQt6 mysql-connector-python pyinstaller bcrypt python-dotenv
```

## Настройка базы данных

Проект использует MySQL/MariaDB. Для локальной разработки можно использовать XAMPP.

База данных по умолчанию:

```text
catcorp
```

Перед запуском сервера нужно создать таблицы проекта и выполнить SQL-миграции из папки `database/`, если они ещё не применялись.

---

## Настройка .env

Сервер берёт параметры подключения к базе данных из файла `.env`.

Создайте файл `.env` рядом с `server.py` на основе `.env.example`:

```env
CATCORP_DB_HOST=127.0.0.1
CATCORP_DB_PORT=3307
CATCORP_DB_USER=catcorp_app
CATCORP_DB_PASSWORD=change_this_password
CATCORP_DB_NAME=catcorp
```

Файл `.env` нельзя выкладывать на GitHub.

## Пользователь MySQL для приложения

Не рекомендуется запускать приложение от `root`.

Для проекта используется отдельный пользователь MySQL, например:

```text
catcorp_app
```

Пример SQL находится в:

```text
database/security_step2_mysql_user.sql
```

Пользователь приложения должен иметь только необходимые права на базу `catcorp`.

## Запуск сервера

Перед запуском клиента должен быть запущен сервер:

```powershell
python server.py
```

По умолчанию сервер слушает:

```text
0.0.0.0:5000
```

Это значит, что сервер доступен не только с текущего ПК, но и с других устройств в локальной сети, если Windows Firewall разрешает подключение к порту `5000`.

---

## Запуск клиента

```powershell
python client.py
```

На экране входа можно нажать кнопку **«Сервер»** и указать IP компьютера, на котором запущен `server.py`.

Для запуска на другом ПК нужно указать LAN-IP серверного компьютера, например:

```text
192.168.1.25
```

Порт по умолчанию:

```text
5000
```

---

## Сборка клиента в exe

```powershell
pyinstaller --noconfirm --onefile --windowed --name CatCorpClient client.py
```

Готовый файл появится здесь:

```text
dist/CatCorpClient.exe
```

Для отладки можно собрать консольную версию:

```powershell
pyinstaller --noconfirm --onefile --console --name CatCorpClientDebug client.py
```

## Локальные файлы рядом с exe

Минимально рядом с `.exe` может лежать только сам клиент:

```text
CatCorpClient.exe
```

Дополнительные файлы создаются только при необходимости:

```text
auth_token.json
settings.json
server_config.json
```

Назначение файлов:

* `auth_token.json` — создаётся только если включено **«Запомнить вход на этом ПК»**;
* `settings.json` — создаётся после изменения настроек клиента;
* `server_config.json` — создаётся после изменения host/port через кнопку **«Сервер»**.

Эти файлы локальные и не должны попадать в GitHub.

## Уведомления

В CatCorp есть уведомления через системный трей Windows.

Поддерживается:

* звук уведомлений;
* скрытие текста сообщений в уведомлениях;
* отключение уведомлений для конкретного личного чата;
* отключение уведомлений для конкретной группы;
* сохранение настроек уведомлений локально в `settings.json`.

Отключение уведомлений не удаляет чат и не отключает счётчик непрочитанных сообщений. Оно отключает только звук и всплывающее уведомление.

## Безопасность

В проект уже добавлены базовые меры безопасности:

* клиент не подключается напрямую к базе данных;
* пароль не хранится в открытом виде;
* пароли хэшируются через `bcrypt`;
* старые SHA-256-хэши паролей поддерживаются только для мягкой миграции и обновляются при успешном входе;
* токен входа не вшивается в `.exe`;
* токен создаётся только при включённой настройке **«Запомнить вход»**;
* при новом входе старые auth-токены пользователя удаляются;
* настройки базы данных вынесены в `.env`;
* для базы используется отдельный пользователь MySQL вместо `root`;
* добавлена защита от перебора пароля;
* добавлено ограничение длины сообщений;
* повторный вход в уже авторизованном TCP-соединении отклоняется.

Важно: TLS-шифрование TCP-трафика пока не включено. Для реального корпоративного использования его стоит добавить перед полноценным внедрением.

## Ограничение попыток входа

После нескольких неудачных попыток вход временно блокируется.

Текущая логика:

```text
5 неудачных попыток
15 минут блокировки
```

Таблица для этого:

```text
login_attempts
```

SQL-файл:

```text
database/security_step3_login_attempts.sql
```

## Ограничение длины сообщений

Сервер ограничивает длину личных и групповых сообщений.

Текущий лимит:

```text
4096 символов
```

Это защищает сервер и базу данных от слишком больших сообщений.

## Проверка в локальной сети

1. Запустите `server.py` на основном компьютере.
2. Узнайте IP этого компьютера:

```powershell
ipconfig
```

3. На другом ПК запустите клиент.
4. На экране входа нажмите **«Сервер»**.
5. Укажите IP компьютера с сервером и порт `5000`.

Проверка доступности порта:

```powershell
Test-NetConnection 192.168.1.25 -Port 5000
```

Если порт недоступен, проверьте:

* запущен ли `server.py`;
* правильный ли IP указан в клиенте;
* открыт ли порт `5000` в Windows Firewall;
* находятся ли устройства в одной локальной сети.
